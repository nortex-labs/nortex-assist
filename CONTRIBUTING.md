# Разработка Nortex Assist

Здесь всё, что нужно для работы с кодом: сборка, тесты, отладка, выпуск версий и правила описания релизов.
Инструкция для пользователей лежит в [README.md](README.md).

## Сборка

Нужны:

- Rust stable с набором MSVC (`rustup default stable-x86_64-pc-windows-msvc`);
- Visual Studio Build Tools с компонентом «Разработка классических приложений на C++»;
- для установщика — [Inno Setup 6](https://jrsoftware.org/isinfo.php).

```powershell
cargo run                # debug-сборка с консолью и отладочными переменными
cargo build --release    # target\release\nortex-assist.exe (около 22 МБ)
cargo test               # обычные тесты
cargo test -- --ignored  # живой тест: скачивает последний выпуск с GitHub и сверяет контрольные суммы
```

Установщик собирается после `cargo build --release`:

```powershell
& "$env:LOCALAPPDATA\Programs\Inno Setup 6\ISCC.exe" installer\nortex-assist.iss
# результат: installer\Output\NortexAssist-Setup-X.Y.Z.exe
```

Если Inno Setup ставился для всех пользователей, `ISCC.exe` лежит в `C:\Program Files (x86)\Inno Setup 6\`.

## Как устроен проект

| Путь | Что там |
|------|---------|
| `src/main.rs` | окно, горячие клавиши, трей, логика диалога и настроек |
| `src/llm.rs` | запросы к Gemini и Groq, промпты, разбор ошибок |
| `src/clip.rs` | буфер обмена, выделенный текст, скриншоты |
| `src/native.rs` | вызовы Win32: фокус, прозрачность окна, захват экрана, автозапуск |
| `src/config.rs` | настройки и их проверка |
| `src/crypto.rs` | шифрование AES-256-GCM, ключ под защитой DPAPI |
| `src/history.rs` | история (до 300 записей) |
| `src/update.rs` | проверка и установка обновлений с GitHub Releases |
| `ui/main.slint` | весь интерфейс на [Slint](https://slint.dev) |
| `installer/nortex-assist.iss` | скрипт установщика Inno Setup |

Интерфейс рисуется процессором (software renderer Slint). Отрисовка через OpenGL держала около 120 МБ памяти даже со скрытым окном.

## Отладочные переменные

Работают только в debug-сборке (`cargo run`), в release они игнорируются.

| Переменная | Зачем |
|------------|-------|
| `NORTEX_GEMINI_ORIGIN`, `NORTEX_GROQ_ORIGIN` | адрес вместо настоящего API, например локального mock-сервера `http://127.0.0.1:8765` |
| `NORTEX_GEMINI_KEY`, `NORTEX_GROQ_KEY` | ключ без ввода в настройках (с `NORTEX_GROQ_KEY` провайдером становится Groq) |
| `NORTEX_DATA_DIR` | отдельная папка данных вместо `%APPDATA%\NortexAssist`, чтобы не трогать свои настройки и историю |
| `NORTEX_OVERLAY` | включить режим поверх игр |

Программа не запускается второй раз, пока работает первая копия. Перед `cargo run` закройте установленную версию: правый клик по значку в трее → «Выход».

## Выпуск новой версии

Программа ищет обновления на GitHub Releases по **точным именам файлов**. Если имя файла будет другим, обновление молча не придёт.

1. Поднимите версию в двух местах, они должны совпадать:
   - `version` в `Cargo.toml`;
   - `MyAppVersion` в `installer/nortex-assist.iss`.
2. Соберите программу и установщик:
   ```powershell
   cargo build --release
   & "$env:LOCALAPPDATA\Programs\Inno Setup 6\ISCC.exe" installer\nortex-assist.iss
   ```
3. Напишите описание выпуска по [шаблону](docs/RELEASE_NOTES_TEMPLATE.md) (правила ниже) и сохраните, например, в `notes.md`.
4. Создайте выпуск с тегом `vX.Y.Z` и двумя файлами:
   ```powershell
   gh release create vX.Y.Z `
     installer\Output\NortexAssist-Setup-X.Y.Z.exe `
     target\release\nortex-assist.exe `
     --title "Nortex Assist X.Y.Z" --notes-file notes.md
   ```
   - `NortexAssist-Setup-X.Y.Z.exe` нужен установленным копиям: они запускают его тихо.
   - `nortex-assist.exe` нужен портативным копиям: они подменяют свой exe и перезапускаются.
5. Проверьте выпуск: `cargo test -- --ignored`. Тест скачивает файлы и сверяет их с контрольными суммами, которые показывает GitHub.

Версии нумеруются по [semver](https://semver.org/lang/ru/): `X.Y.Z`, тег `vX.Y.Z`.

## Как писать описание релиза

Описание читают пользователи, а не разработчики. Шаблон: [docs/RELEASE_NOTES_TEMPLATE.md](docs/RELEASE_NOTES_TEMPLATE.md).

1. **Пишите для пользователя.** Не «рефакторинг модуля capture», а «Скриншот теперь появляется сразу после выделения области».
2. **Заголовок:** «Nortex Assist X.Y.Z» и дата выпуска.
3. **Первая строка:** одно предложение о главном в этой версии.
4. **Разделы:** «Новое», «Улучшено», «Исправлено», «Важно». Пустые разделы убирайте. «Важно» нужен, если пользователю надо что-то сделать вручную, например заново ввести ключ.
5. **Один пункт — одно изменение.** Начинайте с действия или результата («Добавлена…», «Исправлено: …»). Не длиннее двух строк.
6. **Исправления описывайте по симптому**, который видел пользователь, а не по причине в коде.
7. **Если поведение изменилось**, скажите, что изменилось и где это настраивается.
8. **Предупреждайте**, если меняется привычное: горячие клавиши, сброс настроек.
9. **Внизу:** ссылки на установщик и портативный exe, контрольные суммы (если есть) и строка «Полный список изменений: сравнение с прошлой версией» со ссылкой на compare.
10. **Версия** по semver: `X.Y.Z`, тег `vX.Y.Z`. Версия в `Cargo.toml` и `installer/nortex-assist.iss` совпадает с тегом.
11. **Одинаковая структура в каждом релизе**, чтобы пользователь привык её читать.
12. **Не обещайте того, чего нет.** Не пишите «улучшена производительность» без конкретики.

## История проекта

Nortex Assist — порт Electron-приложения InputHost 1.4.0 на Rust и Slint.

Что не перенесено из оригинала намеренно:

- горячая клавиша «стереть ключ и выйти»;
- имя процесса `InputHost`: оно совпадало с системным процессом Windows.

«Упрощённое окно» оригинала перенесено как «Режим поверх игр», но окно остаётся обычным видимым окном.
